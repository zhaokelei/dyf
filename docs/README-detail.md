# 基于郑州工商学院德育分统计办法的德育分后台管理系统（PHP + MySQL 实现）

[简体中文](../README.md) | [English](../README.en.md)

本系统采用 **Laravel 13 + PHP 8.4**，数据库为 **MariaDB 11.4（MySQL 兼容）**，前端为 **Vue 3 + Inertia + Vite + Tailwind CSS 4**。

界面按 **vue-pure-admin** 的布局与交互规范重构：深色可折叠侧栏、顶部面包屑、标签页、刷新/全屏、主题色切换、卡片化内容，同时保留移动端底部导航与卡片视图。品牌使用郑州工商学院校徽与校名。页面切换、弹窗、开关、按钮、表格悬停与侧栏均加入轻量动效，并支持系统“减少动态效果”设置。

> 项目源码位于仓库根目录；安装部署请先阅读根目录 [INSTALL.md](../INSTALL.md)。
>
> **安装部署请先阅读根目录 [INSTALL.md](../INSTALL.md)**：包含服务器要求、install.php 向导、命令行安装、验收清单与维护约定。

## 1. 已实现功能

### 学期与成绩

- **学期制**：每学年包含第一学期、第二学期，申请与成绩分别归档，保留每学期明细。
- **学年汇总**：排行榜、我的德育分、数据统计均可切换“学期”或“学年汇总”，学年成绩由两个学期实时聚合。
- **基础分**：默认 40 分，可在系统设置修改；总分 = 基础分 + 加分 - 扣分，不设上限，最低 0 分。
- **多条记录**：同一学生同学期同类别允许多条有效记录。
- **成绩撤销**：管理员可手工撤销；申诉通过的扣分记录会标记为“已撤销”，不再计入总分，但保留记录与审计。

### 排行榜

- **排行范围**：全校总榜、学院榜、年级榜、班级榜
  - 学院榜选择学院后，展示该学院学生排名
  - 年级榜按“学院（可选）+ 年级”展示该年级学生排名
  - 班级榜选择具体班级后展示本班排名
- **时间维度**：周排行、月排行、自定义日期范围，以及学期排行、学年汇总排行
- **筛选**：专业、姓名/学号
- **分页**：每页 10 / 20 / 50 / 100 条，或选择“全部”一次显示当前范围内所有学生
- Excel 导出会带上当前排行范围、学期/学年与周期
- 总排行按基础分 + 累计加减分；周/月/自定义按本期净分排序

### 学生端

- 登录 / 退出 / 修改密码
- 工作台：当前学期总分、最近申请、待处理申诉、公告
- 我的德育分：学期/学年切换、类别汇总、明细、撤销标记、Excel 导出
- 提交申请：选择类别、填写分值、上传**图片**证明（JPG / PNG / WebP，不再接受 PDF）
- 我的申请：状态/学期筛选、撤回待审或被驳回的申请
- 集体申请记录：查看涉及本人的教师集体申请
- **扣分申诉**：对扣分记录提交申诉理由与图片证明，查看处理进度与结果
- 公告查看

### 教师端

- 工作台、集体申请列表、成员明细、撤回
- 发起集体申请：Excel/CSV 成员导入、模板下载、证明材料（PDF/图片）
- 排行榜只读查看、公告

### 管理员端
### 组织与分级管理

学校组织层级：**学校 → 学院 → 专业 → 年级 → 班级**。其中**专业仅作为查询、统计和排行榜筛选维度，不单独设置专业管理员**。

- **超级管理员**：创建/编辑/删除学院、专业、班级，授权学院管理员，拥有全校数据权限。
- **学院管理员**：仅可管理授权学院内的学生/教师、专业、班级、审核、成绩、申诉与统计；并统一配置本学院辅导员管理哪些班级。
- **辅导员（`class_admin`）**：
  - 可按“专业 + 年级”授权，自动覆盖该年级下全部班级；
  - 也可按具体班级授权；
  - 支持同时授权多个年级/多个班级，例如一个辅导员同时管理 2026 级与 2027 级；
  - 可管理范围内学生、个人申请审核、成绩、申诉、排行榜与统计；
  - 不可创建用户、不可审核集体申请（集体申请只读）。
- **数据范围**：所有列表、统计、导出和审核均按学院/专业/年级/班级过滤；跨范围访问返回 403。
- **集体申请**：按成员所属学院/班级决定可见范围；学院管理员可审核涉及本院成员的集体申请。

### 管理员配置入口（组织管理）

- **系统管理员**：新增/编辑/删除学院、专业、班级；授权或撤销学院管理员。
- **学院管理员**：维护本学院专业、班级；在学院卡片点击“统一配置辅导员”，勾选该辅导员负责的多个班级，一次保存即可增删改其班级范围。
- 也可在专业行按“专业 + 年级”批量配置辅导员，自动覆盖该年级全部班级。
- 修改授权：点击已授权标签旁的 X 撤销后重新授权；删除学院/专业/班级时，如仍有下级用户或班级，系统会阻止删除。
- 专业只用于查询、统计和排行榜筛选，不设专业管理员。

### 注册入口

- 登录页“注册账号”进入统一注册页：先选择“学生注册”或“教师注册”，两种身份使用独立表单。
- 学生注册不需要邀请码；教师注册必须填写教师邀请码。

### 学生自主注册

- 注册页选择学生身份后进入 `/register/student`（可在系统设置中关闭）。
- 注册时选择学院、专业、年级、班级，账号为本人学号，密码由学生自行设置。
- 服务端校验班级与学院/专业/年级的归属关系，学号唯一。
- 可选择“注册需要管理员审核”：开启后新账号默认禁用，管理员启用后方可登录。
- 清空测试数据后暂无班级，学生注册默认关闭；导入班级后再开启。

### 教师自主注册

- 注册页选择教师身份后进入 `/register/teacher`，教师只需选择**学院**，不绑定专业、年级或班级。
- 必须填写管理员在“系统设置”中配置的**教师注册邀请码**。
- 邀请码正确即注册成功，账号默认启用，可直接用工号和密码登录。
- 学生注册接口强制创建 `student` 角色，无法通过参数注册教师；教师身份由邀请码校验。
- 管理员可在“用户管理”中手动停用账号。


- 审核中心：个人/集体申请统一审核、核定分值、驳回、批量通过/驳回
- **扣分申诉审核**：查看申诉理由与图片证明，通过后自动撤销扣分，驳回需填写原因
- 排行榜与周期排行、成绩管理、数据统计
- 用户管理：新增、编辑、启禁用、重置密码、Excel/CSV 批量导入
- 全部列表页统一支持每页 10 / 20 / 50 / 100 条或“全部显示”
- 类别管理、**学期管理**（一键创建一学年两学期、设为当前、删除未使用学期）
- 公告管理、审计日志、系统设置
- 所有审核、成绩、申诉、用户、类别、学期、公告操作均写入审计日志

## 2. 快速启动（本机已配置完成）

### 环境要求

- Windows 10/11 x64（便携启动脚本为 Windows 批处理）
- 已随项目提供 PHP 8.4 与 MariaDB 11.4 便携运行时；系统需具备 Visual C++ 2015–2022 运行库
- Node.js 20+（仅重新构建前端、运行 UI 检查）
- Python 3.10+（仅运行 HTTP 冒烟测试）
- 浏览器：Chrome / Edge / Safari / Firefox 最近两个版本

### 方式一：双击脚本

1. 双击 `run.bat`：自动启动 MariaDB（若未运行）和 Web 服务。
2. 浏览器访问 <http://localhost:8080>。
3. 停止：双击 `stop.bat`。

局域网访问：`http://本机IP:8080`（防火墙需放行 8080；生产请使用 Nginx/Apache，不建议用 `artisan serve` 对外）。

### 方式二：命令行

```bat
runtime\mariadb\bin\mariadbd.exe --basedir=%CD%\runtime\mariadb --datadir=%CD%\runtime\mariadb-data --port=3307 --bind-address=127.0.0.1 --console
runtime\php\php.exe artisan serve --host=0.0.0.0 --port=8080
```

### 首次在新目录部署

执行 `setup.bat`：初始化 MariaDB 数据目录（若缺失）、创建数据库与应用账号、复制 `.env`、生成 APP_KEY、安装 Composer/npm 依赖、执行迁移与种子、构建前端。然后双击 `run.bat`。

> `runtime/`、`vendor/`、`node_modules/`、`public/build/` 不纳入 Git；当前工作区已包含完整可运行文件。

## 5. 业务规则

1. **学期**：申请与成绩提交时固定使用当前学期；后台可随时切换当前学期。
2. **学年汇总**：`year:2026-2027` 会自动聚合该学年两个学期的成绩，不额外生成学年记录。
3. **总分**：`基础分 + 加分 - 扣分`，不设上限，最低 0；已撤销记录不计入。
4. **周期排行**：本周/本月/自定义范围按成绩记录创建时间（即审核通过入账时间）筛选；周期排行按“本期净分”排序，总排行按累计总分排序。
5. **证明材料**：学生个人申请与扣分申诉仅接受图片（JPG/PNG/WebP）；教师集体申请证明材料支持 PDF 与图片。
6. **审核状态机**：`pending → approved / rejected`；待审/被驳回可撤回为 `withdrawn`；已通过不可撤回、不可重复审核。
7. **扣分申诉**：
   - 仅本人、有效的负分记录可申诉；同一记录同时只能存在一条待处理或已通过的申诉。
   - 申诉必须上传图片证明。
   - 管理员通过后，原扣分记录标记为撤销并停止计分；驳回则维持原扣分。
   - 被驳回后可再次申诉（仍受“待处理/已通过”限制）。
8. **分级权限**：
   - 超级管理员（`admin`）拥有全校权限。
   - 学院管理员（`college_admin`）通过 `college_admin_user` 授权一个或多个学院，数据范围按学生 `college_id` / 教师 `college_id` 过滤。
   - 辅导员（`class_admin`）可同时拥有年级授权（`grade_admin_user`）与班级授权（`class_admin_user`），数据范围取并集：
     - 年级授权：覆盖该专业该年级下所有班级，适合一个辅导员管理多个年级；
     - 班级授权：仅覆盖指定班级。
   - 学院管理员可创建本学院学生/教师、管理专业/班级并授权年级或班级辅导员；辅导员不可创建用户。
   - 集体申请按成员所属学院/班级可见；辅导员只读，学院管理员可审核。
   - 学生可在登录页自主注册，选择学院/专业/年级/班级，账号为学号，密码自行设置；注册开关与审核开关在系统设置中配置。
9. **审计**：所有关键操作写入 `audit_logs`。

## 8. 生产部署建议

1. Nginx/Apache + PHP-FPM，站点根目录指向 `public`，不要暴露 `storage`、`runtime`。
2. `.env`：`APP_ENV=production`、`APP_DEBUG=false`、`APP_URL=https://域名`，更换 APP_KEY、数据库密码与所有默认密码。
3. 使用真实 MySQL 8/MariaDB，独立低权限账号；定期备份数据库、`storage/app/private/evidence` 与 `storage/app/private/appeals`。
4. 启用 HTTPS 与安全响应头；上传目录禁止脚本执行。
5. `php artisan config:cache && php artisan route:cache`。
6. 开启 PHP OPcache；Nginx 开启 gzip/brotli，并给 `public/build` 静态资源设置长期缓存。
7. 单机部署可将 `SESSION_DRIVER`、`CACHE_STORE` 改为 `file`，多机部署使用 Redis。
8. 系统设置与学期数据已做请求级缓存；登录页品牌图已压缩（校徽/Logo 使用 `*-168.png`、`*-480.png` 等优化版本）。
9. 不要使用 `run.bat` 中的 PHP 内置服务器对外提供服务。
